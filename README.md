# 房贷测算台

一个纯前端的房贷测算工具：等额本息 / 等额本金逐月拆解、公积金与商贷组合贷、
任意年份提前结清的总支出与省息测算。零构建、零第三方运行时依赖。

## 快速开始

```bash
node tools/serve.mjs          # 打开 http://127.0.0.1:8080
```

页面使用 ES Modules，**不能用 `file://` 直接双击打开**（浏览器会以 CORS 为由拒绝加载模块），
必须经由本地 HTTP 服务。`tools/serve.mjs` 只依赖 Node 内置模块，无需 `npm install`。

## 功能

| 模块 | 能力 |
| --- | --- |
| 贷款构成 | 纯商贷 / 纯公积金 / 组合贷，组合贷两笔可各自选择还款方式 |
| 利率输入 | 直接输入年利率，或用 LPR ± 基点快捷换算，两者实时互相印证 |
| 逐年重定价 | 商业贷款按「LPR + 加点」逐年重定价，重定价后按剩余本金与剩余期数重算月供 |
| 月供轨迹 | 显式画出每次重定价造成的月供台阶，并标出重定价时点 |
| 逐月拆解 | 每期月供、本金、利息、剩余本金；组合贷可按笔查看各自月供 |
| 按年汇总 | 每年还款总额与利息占比，等额本金下逐年下降一目了然 |
| 提前结清 | 第 0~N 年每个节点：结清现金、全周期总支出、省下利息、省息比例 |
| 方式对比 | 同一笔贷款在两种还款方式下的总利息与月供压力差 |

## 计算规则

金额在内部一律用**整数分**流转，每期四舍五入到分，末期以剩余本金兜底。
这样 360 期跑下来本金合计精确等于贷款额，不会出现"还完了还差 0.01 元"的浮点残差。

### 等额本息

```
月供 M = P · i · (1+i)^n / ((1+i)^n − 1)
当期利息 = 上期末剩余本金 · i
当期本金 = M − 当期利息
```

i 为月利率，取 `年利率 / 12`（名义利率按月计息），与国内房贷合同一致，
而不是 `(1+r)^(1/12) − 1` 那种有效年利率换算。

### 等额本金

```
当期本金 = P / n（四舍五入到分）
当期利息 = 上期末剩余本金 · i
月供 = 当期本金 + 当期利息
```

### 提前结清

严格区分两个金额，这是最容易混淆的地方：

- **结清当天要支付** = 剩余本金 + 违约金（当天实际转账金额）
- **全周期总支出** = 已付月供 + 结清当天要支付（这件事从头到尾的总成本）

由此可得两条恒等式，`tests/core.test.mjs` 对每个采样点逐一校验：

```
全周期总支出 = 本金 + 已付利息 + 违约金
省下利息     = 原计划总利息 − 已付利息 − 违约金
```

因为两条路径偿还的本金完全相同，差额只可能来自利息与违约金。

违约金按剩余本金乘以比例计收，并支持设置免罚期（还款满 X 期后不再收取）。

### 利率分段：LPR 逐年重定价

真实房贷的合同结构是 **执行利率 = 重定价日 LPR + 加点**：
加点在整个合同期固定不变，LPR 每 12 期重新取值。

启用后，等额本息在**每个重定价周期起点**按「当时的剩余本金 + 剩余期数 + 新利率」重算月供。
这里有两个容易做错的地方：

1. 不能把新利率套进**原始本金与原始期限**去算——那会得到错误的月供。
2. 不能每期都重算——即使利率没变，逐期四舍五入的累积也会让月供出现
   `4490.44 / 4490.45` 两个值，违背「月供恒定」这条合同约定。因此只在利率
   真正变化时才重算。

等额本金不受影响：每期本金固定，只是按当期利率计息。

LPR 走势是假设，不是预测。快捷情景只作用于前 10 年（更贴近实际预测窗口），
需要更长的假设可逐年手填。快捷情景按 30 年线性外推会把 LPR 减成负数，
看似精确实则荒谬，所以刻意不做。

## 外观主题

深色（黑底 / 暖白 / 低饱和铜色）为默认，浅色为辅，可随系统自动选择，也可在右上角手动切换。
主题由 CSS 变量驱动，图表颜色同样走变量，切换时无需重绘。

```js
document.documentElement.dataset.theme  // 'dark' | 'light'
localStorage.getItem('loanlab-theme')   // 用户手动选择后记住
```

配色集中在 `styles/tokens.css`，改主题只动这一个文件。

## 已知边界

这些是刻意的取舍，不是遗漏：

- **重定价日按「每 12 期」对齐**：实际合同有「每年 1 月 1 日」和「放款日对月对日」两种，
  放款不在 1 月时两者会错开几个月。本工具按对月对日处理。
- **LPR 走势是假设，不是预测**：未来 LPR 无法预知，工具只负责把假设算对。
  需要评估「LPR 涨到多少会怎样」这类问题时，用逐年编辑器填入压力情景即可。
- **公积金不走 LPR**：公积金按国家统一利率，通常也是次年 1 月 1 日统一调整，
  本工具按固定利率处理，可直接填最新值。
- **不含税费**：契税、评估费、保险费、提前还款手续费等不计入。
- **违约金为简化模型**：按剩余本金乘比例，支持免罚期；不模拟"收取 X 个月利息"等按银行差异巨大的规则。
- **部分提前还款未实现**：目前只支持一次性结清。若要支持"还一部分后缩短年限或降低月供"，
  需要以结清点为新起点重建摊销表，`core/` 已按可重入的方式组织，扩展时不必改动现有函数。
- **组合贷期限共享**：两笔共用同一期限，符合银行对组合贷的要求；`mergeSchedules` 本身支持
  期限不一致的表合并，只是界面暂未暴露该入口。
